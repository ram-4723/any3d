# 3D Anything

A bilingual, frame based object explorer. The Next.js frontend is deployable to Vercel; the optional Spring Boot API provides searchable object data. Sample content and generated artwork are marked as placeholders and must be replaced with verified copy and production frame packs before a public factual launch.

## Requirements

- Node.js 20.9+
- Java 21 and Maven 3.9+
- Python 3.10+ with Pillow (`python -m pip install -r scripts/requirements.txt`) to generate placeholder packs

## Local development

1. Generate the three artificial 144 frame packs: `npm run generate-placeholders` from the repository root.
2. Start the frontend: `cd web`, copy `.env.example` to `.env.local`, run `npm install`, then `npm run dev`.
3. Start the API in another terminal: `cd api-server`, copy `.env.example` to `.env`, then run `mvn spring-boot:run`. It uses an in-memory H2 database by default and loads seed JSON from `web/data/objects`.
4. Visit `http://localhost:3000`. The site uses the API when `NEXT_PUBLIC_API_URL` is set and reachable, and falls back to bundled static JSON otherwise.

## Add an object

1. Unzip the frame pack into `web/public/objects/<slug>/`.
2. Add `<slug>.json` to `web/data/objects/` and the API seed folder `api-server/src/main/resources/seed/`.
3. Run `npm run validate-packs` from the repository root. The static fallback reads every JSON entry in `web/data/objects/` automatically.

The pack contract requires `manifest.json`, `poster.webp`, and all declared sequence frames in 1600×900 WebP. Frame numbering starts at 0001 and `{0000}` in patterns is replaced by a zero padded frame number. `explode` and `hotspots` are optional. Placeholder packs generated by the script contain obviously artificial silhouettes and should not be presented as real object photography.

## Tests and checks

- Frontend unit tests: `cd web && npm test`
- Playwright viewer interaction: `cd web && npx playwright install chromium && npm run test:e2e`
- API tests: `cd api-server && mvn test`
- Pack validation: `npm run validate-packs`
- Production frontend build: `cd web && npm run build`

## Deployment

Deploy `web` as the Vercel project root. Leave `NEXT_PUBLIC_API_URL` empty to use static fallback data, or set it to the deployed API origin. Deploy `api-server` as a Java 21 container and configure `DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD`, `DATABASE_DRIVER`, `PORT`, and `CORS_ORIGIN` through the host's environment settings. The included Dockerfile builds the Spring Boot service. The PostgreSQL driver is included; do not commit production credentials.

OpenAPI UI is available at `/swagger-ui.html` when the API runs.
